Mitwirken

Open Firenet ist ein Gemeinschaftsprojekt. Sie müssen nicht programmieren können, um zu helfen: Die nützlichsten Beiträge waren bisher Berichte und Tests von Besitzern von Öfen, zu denen wir selbst keinen Zugang haben.

Berichten Sie, was an Ihrem Ofen funktioniert

Wir können nur an unseren eigenen Öfen testen. Wenn der Stick an Ihrem Ofen funktioniert, fügt ein zweiminütiger Bericht Ihr Modell, Ihre Firmware-Version und Ihre Platine den Listen hinzu und hilft dem nächsten bei seiner Entscheidung.

Bericht „It works on my stove“ erstellen

Besonders gesucht sind Rückmeldungen zu:

  • Öfen mit Firmware 2.30 (bisher eine Rückmeldung), 2.25 (bisher ein Ofen; Zündung noch ungetestet);
  • Modellen, die noch nicht in der Kompatibilitätsliste stehen;
  • Platinen, die noch nicht in der Hardwareliste aufgeführt sind.

Einen Heizzyklus aufzeichnen

Der Stick zeigt an, was der Ofen übermittelt: seinen Zustand, seine Temperaturen, seine Leistung. Wie ein Ofen einen Heizzyklus durchläuft, unterscheidet sich zwischen Modellen und Firmware-Versionen, und wir kennen nur unsere eigenen. Eine Aufzeichnung Ihres Ofens zeigt uns, was tatsächlich passiert, damit die Webseite und Home Assistant alles getreu darstellen können.

  1. Öffnen Sie den Installer (Version 1.10.0 oder neuer) auf einem Rechner in Ihrem Netzwerk, Reiter Aufzeichnen, und klicken Sie vor dem Einschalten des Ofens auf Starten.
  2. Notieren Sie während des Betriebs, was das Display des Ofens in den wichtigen Momenten anzeigt („Reinigung“, „Scheitholz einlegen“...).
  3. Klicken Sie nach dem Zyklus auf Stoppen und dann auf Datei an uns senden.

Der Ofen wird nur ausgelesen, es wird nichts an ihn gesendet, und die Datei enthält weder Ihren WLAN-Namen noch Ihre Adressen. Halten Sie den Rechner während der Aufzeichnung aktiv (kein Ruhezustand). Auf einem Rechner, der durchgehend läuft, wie einem Raspberry Pi, bewirkt der Befehl open-firenet-installer record --ip gefolgt von der Adresse des Sticks dasselbe.

Heizzyklus teilen

Besonders gesucht: ein kompletter Zyklus ab Kaltstart, Scheitholzbetrieb bei einem Kombiofen sowie jedes Modell oder jede Firmware-Version außer einem DOMO mit 2.29.

Ein Problem melden

Ein aussagekräftiger Bericht spart mehrere Nachfragen: Ofenmodell und Firmware-Version, Version des Sticks und die Diagnosedatei des Sticks. Das Formular fragt nach jedem dieser Punkte, und die Seite Fehlerbehebung erklärt, wo sie zu finden sind.

Falls Sie bereit sind, bei der Fehlersuche eine Test-Firmware an Ihrem Ofen auszuprobieren, geben Sie dies im Issue an: Auf diese Weise entstand die Unterstützung für die Firmwares 2.26, 2.27 und 2.28.

Übersetzen

Die Webseite des Sticks, die Home-Assistant-Integration und der Installer sind auf Englisch, Französisch, Deutsch, Italienisch und Spanisch verfügbar. Das Hinzufügen einer Sprache erfordert keine Programmierkenntnisse: Sie kopieren die englischen Texte, übersetzen sie, und eine Prüfung meldet, was noch fehlt.

Übersetzungsleitfaden

Diese Website ist auf Englisch, Französisch, Deutsch, Italienisch und Spanisch verfügbar. Eine Korrekturlesung einer Übersetzung oder eine neue Sprache sind jederzeit willkommen: Jede Seite ist eine HTML-Datei zum Übersetzen, und das README erklärt das Vorgehen.

Dokumentation verbessern

Diese Website hat ihr eigenes Repository: openfirenet.github.io. Die Seiten sind einfache HTML-Dateien im Verzeichnis src/; ihr README erklärt den Build-Prozess. Eine Korrektur, eine klarere Erklärung oder ein fehlender Schritt sind als Pull Request oder einfach als Issue willkommen.

Am Code mitarbeiten

Das Projekt umfasst drei Repositories:

RepositoryBeschreibungProgrammiersprache
open-firenetDie Firmware des Sticks, mit Webseite und APIC++ (Arduino, ESP32-S3), HTML / JavaScript
open-firenet-haDie Home-Assistant-IntegrationPython
open-firenet-installerDer Desktop-InstallerRust (Tauri), JavaScript

Wie wir arbeiten:

  1. Eröffnen Sie zuerst ein Issue oder kommentieren Sie ein bestehendes, um das Vorgehen abzustimmen, bevor Sie Zeit investieren.
  2. Ein Branch pro Änderung, benannt nach dem Issue: fix/42-short-description oder feat/42-short-description.
  3. Führen Sie die Tests aus. Im Firmware-Repository führt ./test/build_and_test.sh alle Prüfungen auf Ihrem Rechner ohne jegliche Hardware aus: das Protokoll, einen simulierten Ofen, die API-Beschreibung und die Übersetzungen.
  4. Ergänzen Sie eine Zeile in CHANGELOG.md unter „Non publié“, auf Englisch, für Benutzer geschrieben: was sich für sie ändert, nicht wie es programmiert wurde.
  5. Eröffnen Sie einen Pull Request, dessen Beschreibung mit Fixes #42 (oder Refs #42 bei Teiländerungen) beginnt. Die automatischen Prüfungen laufen von selbst.

Commit-Nachrichten beginnen mit feat:, fix:, docs: oder chore:: Das Release-Skript liest diese aus, um die nächste Versionsnummer zu bestimmen.

Hinweis zum Ofenprotokoll: Es wurde per Reverse Engineering analysiert, und eine fehlerhafte Nachricht kann dazu führen, dass ein Ofen den Stick ablehnt. Eine Änderung an der Kommunikation mit dem Ofen muss vor dem Zusammenführen an einem echten Ofen getestet werden, idealerweise auf jeder Firmware-Familie. Geben Sie im Pull Request an, was Sie testen konnten und was nicht.
