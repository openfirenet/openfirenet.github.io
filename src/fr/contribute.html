Contribuer

Open Firenet est un projet communautaire. Pas besoin de savoir programmer pour aider : jusqu'ici, les contributions les plus utiles ont été les retours et les essais de personnes qui ont un poêle que nous n'avons pas.

Dites-nous ce qui fonctionne sur votre poêle

Nous ne pouvons tester que sur nos propres poêles. Si la clé fonctionne sur le vôtre, un rapport de deux minutes ajoute aux listes le modèle de votre poêle, sa version de firmware et votre carte, et aide les autres utilisateurs dans leur choix.

Ouvrir un rapport « It works on my stove »

Les retours les plus attendus :

  • les modèles absents de la liste de compatibilité ;
  • les cartes absentes de la liste du matériel.

Enregistrer un cycle de chauffe

La clé affiche ce que le poêle transmet : son état, ses températures, sa puissance. Le déroulement d'un cycle varie selon les modèles et les versions de firmware, et nous ne connaissons que les nôtres. Un enregistrement de votre poêle nous montre ce qui se passe vraiment, pour que la page et Home Assistant l'affichent fidèlement.

  1. Ouvrez l'installeur (version 1.10.0 ou plus récente) sur un ordinateur de votre réseau, onglet Enregistrer, et cliquez sur Démarrer avant d'allumer le poêle.
  2. Pendant la chauffe, notez ce qu'affiche l'écran du poêle aux moments marquants (« Nettoyage », « Mettre des bûches »...).
  3. Cliquez sur Arrêter à la fin du cycle, puis sur Nous envoyer ce fichier.

Le poêle est seulement lu, rien ne lui est envoyé, et le fichier ne contient ni le nom de votre Wi-Fi ni vos adresses. Gardez l'ordinateur allumé, sans mise en veille, pendant l'enregistrement. Sur une machine qui reste allumée, comme un Raspberry Pi, la commande open-firenet-installer record --ip suivie de l'adresse de la clé fait la même chose.

Signaler un problème

Un bon rapport évite plusieurs allers-retours : le modèle du poêle et sa version de firmware, la version de la clé et le fichier de diagnostic de la clé. Le formulaire d'issue demande chacun d'eux, et la page Dépannage indique où les trouver.

Si vous êtes prêt à essayer une version de test sur votre poêle quand nous cherchons une correction, dites-le dans l'issue : c'est ainsi que les firmwares 2.26, 2.27 et 2.28 ont été pris en charge.

Traduire

La page web de la clé, l'intégration Home Assistant et l'installeur existent en anglais, français, allemand, italien et espagnol. Ajouter une langue ne demande pas de savoir programmer : on copie les textes anglais, on les traduit, et une vérification indique ce qui manque.

Guide de traduction

Ce site existe en anglais, français, allemand, italien et espagnol. Une relecture d'une traduction, ou une nouvelle langue, est la bienvenue : chaque page est un fichier HTML à traduire, et le README du site explique comment.

Améliorer la documentation

Ce site a son propre dépôt, openfirenet.github.io. Les pages sont de simples fichiers HTML dans src/ ; son README explique comment les reconstruire. Une correction, une explication plus claire ou une étape manquante sont les bienvenues sous forme de pull request, ou simplement d'une issue qui décrit ce qui vous a gêné.

Contribuer au code

Le projet a trois dépôts :

DépôtRôleLangages
open-firenetLe firmware de la clé, avec sa page web et son APIC++ (Arduino, ESP32-S3), HTML / JavaScript
open-firenet-haL'intégration Home AssistantPython
open-firenet-installerL'installeur pour ordinateurRust (Tauri), JavaScript

Notre façon de travailler :

  1. Ouvrez d'abord une issue, ou commentez-en une existante, pour vous mettre d'accord sur ce qu'il faut faire avant d'y passer du temps.
  2. Une branche par changement, nommée d'après l'issue : fix/42-short-description ou feat/42-short-description.
  3. Lancez les tests. Dans le dépôt du firmware, ./test/build_and_test.sh les lance tous sur votre ordinateur, sans aucun matériel : le protocole, un poêle simulé, la description de l'API et les traductions.
  4. Ajoutez une ligne à CHANGELOG.md sous « Non publié », en anglais, écrite pour les utilisateurs : ce qui change pour eux, pas comment c'est codé.
  5. Ouvrez une pull request dont la description commence par Fixes #42 (ou Refs #42 pour un changement partiel). Les vérifications se lancent toutes seules.

Les messages de commit commencent par feat:, fix:, docs: ou chore: : le script de publication les lit pour choisir le prochain numéro de version.

À propos du protocole du poêle : il a été rétro-ingénié, et une trame erronée peut amener un poêle à refuser la clé. Un changement dans le dialogue avec le poêle doit être essayé sur un vrai poêle, idéalement sur chaque famille de firmware, avant d'être fusionné. Indiquez dans votre pull request ce que vous avez pu tester et ce que vous n'avez pas pu tester.
