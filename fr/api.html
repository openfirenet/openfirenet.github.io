API REST

La clé sert une API JSON sur votre réseau, avec des unités naturelles : températures en °C, puissance en pourcentage, noms de modes lisibles. Ni clé d'API, ni compte.

Référence complète de l'API Fichier OpenAPI

Adresses

Cliquez sur une adresse ou une méthode pour voir son détail dans la référence de l'API.

AdresseMéthodeRôle
/api/stateGETTout en une fois : clé, poêle, capteurs, réglages, diagnostic de la liaison
/api/controlsGET POSTLire ou modifier les réglages (modifications partielles acceptées)
/api/scheduleGET POSTProgrammation hebdomadaire : 14 plages horaires et la température réduite
/api/versionGETVersion du firmware et date de compilation
/api/mqttGET POSTRéglages MQTT et état de la connexion, voir MQTT
/api/txgapGET POSTDélai entre les messages envoyés au poêle (50 à 600 ms, 150 par défaut)
/api/restartPOSTRedémarrer la clé
/api/forgetPOSTEffacer les réglages Wi-Fi et revenir en mode configuration
/logGETJournal en texte brut du dialogue avec le poêle

Qui peut l'appeler

Les programmes de votre réseau : Home Assistant, des scripts, curl, Node-RED. Et la page web de la clé elle-même. Depuis le firmware 4.0, une page d'un autre site ouverte dans un navigateur ne le peut pas : la clé répond 403 à une requête qui indique une autre page comme origine, et n'envoie aucune autorisation cross-origin.

La clé répond à son adresse IP, à un nom sans point et à open-firenet.local. Un autre nom doit d'abord être ajouté dans l'onglet Bridge, Réseau, section « Accès à la page » (ou avec /api/access) ; d'ici là, la clé répond 403 avec un corps JSON qui donne son adresse IP.

Lire l'état

curl http://open-firenet.local/api/state

La réponse est regroupée par thème. Les parties les plus utiles :

ChampSignification
stove.state, stove.model_name, stove.mainboard_versionÉtat de fonctionnement, modèle et version de firmware du poêle
stove.error_code, stove.warning_codeErreur et avertissement en cours, 0 s'il n'y en a pas
sensors.room_temperatureTempérature ambiante, null quand aucune sonde d'ambiance RIKA n'est branchée
sensors.pellets_total_kg, sensors.service_countdown_kgGranulés consommés au total, et ce qu'il reste avant le prochain entretien
controls.on, controls.mode, controls.target_temperature, controls.power_percentLes réglages actuels
version_ack, version_frameSi le poêle a accepté la clé, et dans quelle variante du protocole il a répondu : V3 (firmware 2.29), V28 (2.28), V1 (2.26 / 2.27) ; ? pour un poêle en firmware 2.25, qui utilise des trames numériques
usb.host_connected, usb.rx_bytesSi le poêle voit la clé en USB, et combien d'octets il a envoyés
raw_sensorsToutes les valeurs que transmet le poêle, sous leur nom RIKA

Envoyer des commandes

Envoyez en POST un objet JSON contenant seulement les champs à modifier :

# 21 °C en mode confort
curl -X POST http://open-firenet.local/api/controls \
  -H "Content-Type: application/json" \
  -d '{"target_temperature": 21, "mode": "comfort"}'

# allumer à 80 % de puissance
curl -X POST http://open-firenet.local/api/controls \
  -H "Content-Type: application/json" \
  -d '{"on": true, "power_percent": 80}'
ChampValeurs
ontrue / false
mode"manual", "auto", "comfort"
power_percent30 à 100
target_temperature14 à 28 °C, en degrés entiers (un demi-degré est arrondi)
frost_protection_active, frost_protection_temperaturetrue / false, 4 à 10 °C
room_temperature_offset-4,0 à +4,0 °C
convectionFan1Active, convectionFan1Level, convectionFan1Area (et Fan2)MultiAir : marche/arrêt, 0 = auto ou 1 à 5, ajustement de -30 à +30 %

Depuis le firmware 4.0, les commandes ne sont acceptées qu'en POST et en PUT, et une commande envoyée avant que le poêle ait transmis ses réglages (la clé n'est pas reliée, ou vient de démarrer) est refusée avec 503 et "error": "stove_not_ready". Rien n'a été envoyé au poêle : réessayez quelques secondes plus tard.

Référence complète

Toutes les adresses et tous les champs, avec leur type, leur unité et leur plage, sont dans la référence de l'API. Elle est générée à partir de la description OpenAPI du firmware, que vous pouvez charger dans vos propres outils (visionneuses de documentation, générateurs de clients).

Le format de la programmation et les notes sur le protocole se trouvent aussi dans le dépôt du firmware : README, API REST et PROTOCOL.md.
