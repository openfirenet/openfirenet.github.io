API REST

Il bridge espone un'API JSON sulla vostra rete locale con unità di misura naturali: temperature in °C, potenza in percentuale e nomi leggibili delle modalità. Senza chiavi API né account.

Autorizzazioni di accesso

Programmi della vostra rete locale: Home Assistant, script, curl, Node-RED. Oltre all'interfaccia web del bridge stesso. Dal firmware 4.0, le pagine web aperte in un browser da altri domini non possono effettuare chiamate: il bridge risponde 403 a richieste che indicano un'altra pagina come origine e non invia intestazioni cross-origin.

Il bridge risponde al suo indirizzo IP, a nomi di dominio privi di punto e a open-firenet.local. Qualsiasi altro nome host deve essere preventivamente aggiunto nella scheda Bridge, Rete, sezione "Accesso alla pagina" (o tramite /api/access); in caso contrario il bridge risponde 403 con un payload JSON che indica il proprio indirizzo IP.

Leggere lo stato

curl http://open-firenet.local/api/state

La risposta è suddivisa per sezioni tematiche. Le parti più utilizzate:

CampoSignificato
stove.state, stove.model_name, stove.mainboard_versionStato operativo, modello e versione firmware della stufa
stove.error_code, stove.warning_codeCodici di errore e avviso correnti, 0 in assenza di anomalie
sensors.room_temperatureTemperatura ambiente, null quando non è collegata alcuna sonda RIKA
sensors.pellets_total_kg, sensors.service_countdown_kgPellet complessivamente consumato e residuo prima della prossima manutenzione
controls.on, controls.mode, controls.target_temperature, controls.power_percentLe impostazioni correnti
version_ack, version_frameIndica se la stufa ha accettato il bridge e la versione di protocollo con cui ha risposto: V3 (firmware 2.29), V28 (2.28), V1 (2.26 / 2.27); ? per stufe con firmware 2.25 che utilizzano frame numerici
usb.host_connected, usb.rx_bytesIndica se la stufa riconosce il bridge via USB e quanti byte sono stati ricevuti
raw_sensorsTutti i valori comunicati dalla stufa, con la denominazione RIKA originale

Inviare comandi

Inviate con metodo POST un oggetto JSON contenente solo i campi che desiderate modificare:

# 21 °C in modalità comfort
curl -X POST http://open-firenet.local/api/controls \
  -H "Content-Type: application/json" \
  -d '{"target_temperature": 21, "mode": "comfort"}'

# accensione all'80 % di potenza
curl -X POST http://open-firenet.local/api/controls \
  -H "Content-Type: application/json" \
  -d '{"on": true, "power_percent": 80}'
CampoValori ammessi
ontrue / false
mode"manual", "auto", "comfort"
power_percentda 30 a 100
target_temperatureda 14 a 28 °C, in gradi interi (il mezzo grado viene arrotondato)
frost_protection_active, frost_protection_temperaturetrue / false, da 4 a 10 °C
room_temperature_offsetda -4,0 a +4,0 °C
convectionFan1Active, convectionFan1Level, convectionFan1Area (e Fan2)MultiAir: on/off, 0 = auto o da 1 a 5, regolazione da -30 a +30 %

A partire dal firmware 4.0, i comandi sono accettati esclusivamente con metodi POST e PUT. Un comando inviato prima che la stufa abbia trasmesso le proprie impostazioni (bridge non ancora collegato o appena avviato) viene rifiutato con codice 503 ed errore "error": "stove_not_ready". Nessun comando viene inviato alla stufa: riprovare dopo qualche secondo.

Riferimento completo

Ciascun endpoint e ciascun campo, con tipo, unità e intervallo, è documentato nel riferimento API. È generato automaticamente dalla descrizione OpenAPI del firmware, che potete importare nei vostri strumenti (visualizzatori di documentazione, generatori di client).

Il formato della programmazione oraria e le note di protocollo sono disponibili anche nel repository del firmware: README, API REST e PROTOCOL.md.
