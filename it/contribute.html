Contribuire

Open Firenet è un progetto comunitario. Non occorre saper programmare per essere d'aiuto: finora i contributi più preziosi sono stati i resoconti e le prove di chi possiede una stufa diversa da quelle a nostra disposizione.

Condividete cosa funziona sulla vostra stufa

Possiamo eseguire test solo sulle nostre stufe. Se il bridge funziona sulla vostra, una segnalazione di due minuti aggiunge il modello della stufa, la versione del firmware e la vostra scheda agli elenchi, aiutando altri utenti nella scelta.

Apri una segnalazione « It works on my stove »

Le segnalazioni più attese riguardano:

  • stufe con firmware 2.30 (finora un solo riscontro), con 2.25 (finora una sola stufa; l'accensione non è stata provata);
  • modelli non ancora presenti nell'elenco di compatibilità;
  • schede non ancora presenti nell'elenco dell'hardware.

Registrare un ciclo di riscaldamento

Il bridge mostra quanto comunicato dalla stufa: stato, temperature, potenza. L'evoluzione di un ciclo varia a seconda dei modelli e delle versioni del firmware, e noi conosciamo solo i nostri. Una registrazione della vostra stufa ci mostra cosa accade realmente, affinché la pagina web e Home Assistant possano riprodurlo fedelmente.

  1. Aprite l'installer (versione 1.10.0 o successiva) su un computer della vostra rete, scheda Registra, e premete Avvia prima di accendere la stufa.
  2. Durante la fase di riscaldamento, annotate cosa mostra il display della stufa nei passaggi chiave ("Pulizia", "Aggiungere legna"...).
  3. Al termine del ciclo premete Arresta, quindi Inviaci questo file.

La stufa viene esclusivamente letta, nessun comando viene trasmesso ad essa e il file non include né il nome della vostra rete Wi-Fi né i vostri indirizzi. Mantenete il computer attivo senza sospensione durante la registrazione. Su dispositivi operativi 24 ore su 24, come un Raspberry Pi, il comando open-firenet-installer record --ip seguito dall'indirizzo del bridge esegue la stessa operazione.

Condividi un ciclo di riscaldamento

Casi particolarmente ricercati: un ciclo completo da accensione a freddo, il funzionamento a legna su stufe combinate e qualsiasi modello o firmware diverso da un DOMO su 2.29.

Segnalare un problema

Una segnalazione dettagliata evita diversi scambi: modello e versione firmware della stufa, versione del bridge e file di diagnostica del bridge. Il modulo di apertura issue richiede ciascuno di questi elementi e la pagina Risoluzione problemi indica dove reperirli.

Se siete disposti a provare una versione di test sulla vostra stufa durante l'analisi di una soluzione, indicatelo nell'issue: è così che è stato introdotto il supporto per i firmware 2.26, 2.27 e 2.28.

Tradurre

L'interfaccia web del bridge, l'integrazione per Home Assistant e l'installer sono disponibili in inglese, francese, tedesco, italiano e spagnolo. L'aggiunta di una lingua non richiede competenze di programmazione: si copiano i testi in inglese, si traducono e uno strumento di controllo segnala le stringhe mancanti.

Guida alla traduzione

Questo sito web è disponibile in inglese, francese, tedesco, italiano e spagnolo. Una rilettura di una traduzione o il contributo per nuove lingue sono sempre graditi: ogni pagina è un singolo file HTML da tradurre e il README ne descrive la procedura.

Migliorare la documentazione

Questo sito web risiede in un repository dedicato, openfirenet.github.io. Le pagine sono file HTML lineari nella cartella src/; il README ne descrive la compilazione. Correzioni, spiegazioni più chiare o passaggi mancanti possono essere proposti tramite pull request o semplicemente aprendo un'issue descrittiva.

Contribuire al codice

Il progetto include tre repository principali:

RepositoryDescrizioneLinguaggi
open-firenetFirmware del bridge con server web e API RESTC++ (Arduino, ESP32-S3), HTML / JavaScript
open-firenet-haIntegrazione per Home AssistantPython
open-firenet-installerInstaller desktopRust (Tauri), JavaScript

Come lavoriamo:

  1. Aprite prima un'issue, oppure commentatene una esistente, per concordare gli interventi prima di dedicare tempo allo sviluppo.
  2. Un branch dedicato per ciascuna modifica, denominato in base all'issue: fix/42-short-description o feat/42-short-description.
  3. Eseguite i test. Nel repository del firmware, lo script ./test/build_and_test.sh esegue l'intera suite di verifiche localmente senza alcun hardware: protocollo, simulatore di stufa, schema OpenAPI e traduzioni.
  4. Aggiungete una voce a CHANGELOG.md sotto la sezione « Non publié », redatta in inglese e orientata agli utenti: cosa cambia per loro, non i dettagli tecnici implementativi.
  5. Aprite una pull request la cui descrizione inizia con Fixes #42 (o Refs #42 per modifiche parziali). I controlli automatici si avviano da soli.

I messaggi di commit iniziano con feat:, fix:, docs: o chore:: lo script di rilascio li analizza per determinare l'avanzamento di versione.

Nota sul protocollo della stufa: è stato analizzato tramite reverse engineering e un messaggio errato può indurre la stufa a rifiutare la comunicazione con il bridge. Qualsiasi modifica alla logica di scambio con la stufa richiede una prova su una stufa reale, idealmente per ciascuna famiglia di firmware, prima dell'unione. Descrivete nella pull request ciò che è stato possibile verificare e ciò che non lo è stato.

Domande

Non sapete da dove cominciare o se un'idea è adatta? Aprite un'issue e chiedete: ogni domanda è benvenuta.
